## 当前代码可核验的开发结果

### 架构与业务范围

- 前端采用 React/Vite，后端采用 Django REST API。
- 源 SQL Server 作为只读数据来源；当前 `README.md` 将其定义为“源 SQL Server 始终只读”。
- 当前范围已包含组织、RBAC、审批、主数据、BOM、工艺路线、销售、采购、收退货、应付凭单、库存调拨、盘点与预警。

### 当前字段调整（对话 `01a03192-157a-7542-9f8c-357f19d95183`）

- 产品分类中 `code` 的界面名称为“产品类”，`name` 的界面名称为“描述”。
- 所有当前前端可见的“仓位”名称已统一为“库位”。
- 审批型资源的 `created_by`、`created_at`、`updated_by`、`updated_at` 由服务端根据当前登录账号和服务器时间写入，并在序列化层设置为只读。
- 库位模型增加 `location_attribute`，并新增迁移 `backend/migrations/0021_location_attribute.py`，用于匹配源库 `v_loc_mstr_type.loc_cost_type`。
- 为避免破坏既有逻辑，`parent`、`code_prefix` 和 `no_stock_movement` 等持久化字段仍保留在模型中；其中不符合当前表单要求的字段仅从界面隐藏。
- 已记录的验证结果：Django 后端测试 7 项通过、`makemigrations --check --dry-run` 无差异、`npm run build` 通过。

## 当前已知运行问题与处置

1. 库位和物料信息请求失败：接口 `/api/location/` 与 `/api/material/` 返回 `401 认证令牌无效`。原因是浏览器本地保存的历史登录 token 失效；退出并重新登录即可刷新 token。
2. 新增字段迁移尚未在当前运行数据库应用：`0021_location_attribute` 显示未应用。重新登录后，应在后端目录执行：

   ```powershell
   python backend\manage.py migrate
   ```

   否则库位接口可能因缺少 `location_attribute` 列继续失败。
